# Raw 探活体系实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ] ) syntax for tracking.

**Goal:** 搭建 raw API 探活体系——清理过期文档、写探活脚本（83 个待建 raw API 真实调用一次，五态判定）、产出 JSON 真相源并自动同步到 API清单.md 探活列。

**Architecture:** 探活脚本 scripts/probe_raw.py 复用 dw_cli.core.client（build_client + build_runtime，RegionId 注入不可绕过）+ 复用 dw_cli.commands.raw 的反射逻辑（_resolve_request_class / _request_fields / _coerce）。分三批跑（只读自动 / 低危写自动清理 / 高危写列清单待授权），结果写 docs/raw-probe-result.json（单一真相源），--sync 子命令把 JSON 同步到 API清单.md 的"私有云探活"列。

**Tech Stack:** Python 3.10+ / alibabacloud-dataworks-public20200518 SDK / 已有 dw-cli core 层。

**Spec:** docs/superpowers/specs/2026-07-06-raw-probe-design.md

### Task 3: 探活脚本主体

**Files:** Create scripts/probe_raw.py

**职责**：反射 API -> 分类 -> 真调 -> 五态判定 -> 写 JSON。

- [ ] Step 1: 写 scripts/probe_raw.py

关键组件：
1. sys.path 插入 dw-cli 目录，from dw_cli.core import client；from dw_cli.commands.raw import _resolve_request_class, _request_fields, _coerce
2. 常量: RESULT_FILE=docs/raw-probe-result.json, API_LIST_FILE=API清单.md
3. 五态: a=可用 b=接口可用需调参 c=未实现(404) d=存在需权限(403) e=未定(超时/网络)
4. STATUS_ICONS 映射
5. READ_PREFIXES=(list_,get_,query_,search_,describe_,count_,check_), HIGH_RISK_PREFIXES=(delete_,deploy_,stop_,terminate_,offline_)
6. classify_api(api): manual_required or high_risk前缀 or update_/start_ -> high-write; create_ -> low-write; read前缀或默认 -> read
7. load_result()->dict: 读 JSON，不存在返回空结构
8. save_result(data): 更新 probed_at，写 JSON
9. _to_jsonable(obj): to_map() / dict / list 递归
10. _extract_evidence(resp_or_exc, is_exception): 提取 http_status/error_code/error_message/evidence
11. judge_status: 五态判定（exception: notfound/invalidaction->c, 401/403/forbidden->d, timeout/connect->e, 其它->b; 正常: success=True->a, code含invalidaction->c, forbidden->d, 其它->b）
12. probe_one(api_name, params): 反射Request类->构造参数->build_client+build_runtime->getattr调用->judge->返回结果dict
13. parse_api_list(): 读API清单.md，找状态列含"待建(raw)"的行，提取反引号里的api名
14. run_batch(category, resume, regenerate): 筛选目标->逐个probe_one->每个存JSON->低危写探完自动cleanup->打印摘要
15. _extract_id(result, id_field): 从evidence JSON提取create出的id
16. sync_to_api_list(): 读JSON->改API清单.md待建(raw)行的探活列(填icon)
17. main(): argparse --category/--api/--resume/--regenerate/--sync

- [ ] Step 2: python scripts/probe_raw.py --help 验证无 import 错误
- [ ] Step 3: python scripts/probe_raw.py --category high-write 验证列清单不执行
- [ ] Step 4: python scripts/probe_raw.py --sync 验证不破坏 API清单.md（JSON 空时同步 0 行）
